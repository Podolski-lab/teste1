- (decision) Modo de trabalho: Coaching path. Propósito: build-substrate (Claude implementa o produto para o usuário) + artefato visual adicional no Finalize (deck/HTML) para entendimento do usuário e apresentação a terceiros.
- (constraint) Restrição de plataforma confirmada via pesquisa web: Skill customizada da Alexa NAO pode abrir microfone/esperar resposta proativamente sem sessão iniciada pelo usuário. Reminders API é mão-única (só fala). Mecanismo viável: Custom Tasks integradas a Alexa Routines - routine dispara Custom Task, que abre sessão real de diálogo (pergunta/espera/retry). Fontes: developer.amazon.com docs Proactive Events, Alexa Reminders, Manage Skill Sessions, Custom Triggers for Routines, Integrate Custom Task with Alexa Routines.
- (direction) Caminho proposto: Rotinas de horario fixo (resumo semanal sexta 18h/domingo 20h) disparam Custom Task diretamente. Rotinas de horario dinamico (lembrete/checkpoint por tarefa, dependente do Google Calendar) usam Custom Triggers for Routines, disparados programaticamente pelo backend na hora certa. Requer setup manual do usuario no app da Alexa (criar as Rotinas uma vez) - gap novo em relacao ao PRD/UX, que so previa config manual de pilares no backend.
- (decision) Hospedagem: Lambda auto-gerenciado (nao Alexa-hosted Skill) - precisa de EventBridge Scheduled Rule proprio para o polling, que Alexa-hosted pode nao permitir com liberdade total.
- (decision) Linguagem: Node.js (ASK SDK v2) - caminho mais documentado/maduro para Alexa Custom Skills.
- (decision) Agendamento dinamico: polling periodico (Lambda em cron via EventBridge Scheduled Rule, ex. a cada 10min) le o Google Calendar e dispara Custom Trigger quando alguma tarefa esta na hora - preferido a agendamento dinamico por evento (over-engineering pro caso), consistente com a tolerancia de atraso ja documentada no FR-1 do PRD.
- (decision) Armazenamento: DynamoDB - mapeamento pilar/proposito por evento (FR-11), historico de checkpoints, dados do resumo semanal. Par padrao com Lambda no free tier da AWS.
- (decision) Ambiente: conta AWS ainda precisa ser criada do zero. Credenciais Google Calendar API/OAuth tambem partem do zero.
- (decision) Deploy: opcao (a) - infraestrutura como codigo (IaC) preparada e entregue como comandos/scripts para o usuario rodar localmente com suas proprias credenciais. Claude nao recebe credenciais AWS neste ambiente.
- (decision) Paradigma: Hexagonal leve (Ports & Adapters). Camadas: interacao (ASK SDK RequestHandlers no Lambda da Skill + entrypoint do Lambda de polling), dominio (regras de pilar/proposito, maquina de estado do checkpoint, calculo do resumo semanal), infraestrutura (repositorio DynamoDB, cliente Google Calendar API, cliente Alexa Trigger/Reminders API). Dominio nunca importa AWS SDK ou ASK SDK diretamente.
- (decision) Dois entrypoints Lambda (Skill handler + Poller agendado) compartilham a MESMA camada de dominio - logica nunca duplicada entre os dois; ambos importam do mesmo modulo de dominio.
- (decision) DynamoDB e fonte unica de verdade para estado de tarefa/checkpoint - nenhum entrypoint mantem estado em memoria entre invocacoes. Um item por instancia de tarefa (evento de calendario + data), com campo de status com transicoes explicitas (pendente -> lembrete_enviado -> aguardando_checkpoint -> respondido/sem_resposta/reagendado).
- (decision) Contrato de Custom Trigger: duas fontes de trigger fixas e pre-registradas - 'reminder-trigger' e 'checkpoint-trigger' - cada uma mapeada a uma Rotina/Custom Task propria na Alexa. Poller dispara o trigger certo com payload contendo dados da tarefa (pilar, proposito, task_id). Resumo semanal usa Rotinas de horario fixo direto (sem Custom Trigger).
- (version) Stack fixada apos pesquisa web: AWS Lambda runtime nodejs24.x (LTS atual, suportado ate abr/2028); ask-sdk-core ^2.14.0 (sem release recente - diretivas de Custom Task podem exigir construcao manual de JSON se o SDK nao tiver builder tipado; verificar na implementacao).
- (decision) Config de pilar/proposito por evento (FR-11): tabela DynamoDB separada (PillarConfig), editada manualmente por Claude via AWS CLI/console - nao arquivo de codigo, para consistencia com a camada de persistencia e sem precisar de redeploy pra ajustes.
- (event) Spine destilado a partir do memlog: 6 ADs (dominio isolado, dois entrypoints compartilhando dominio, DynamoDB fonte unica de verdade, contrato de Custom Trigger, config como dado, credenciais fora da sessao), stack fixada, diagramas de conteineres/deployment/ERD, source tree, Capability Map cobrindo FR-1 a FR-12 e os 3 NFRs, secao Deferred.
- (version) AWS SAM CLI verificado via pesquisa web (nao registrado no momento da decisao original): ativamente mantido em 2026, ultimo update jul/2026, adicionou suporte a CloudFormation Language Extensions em mai/2026. Confirma escolha como ferramenta de IaC/deploy.
- (question) Gate de revisao (4 relatorios paralelos) encontrou 2 criticos + 2 altos + achados medios/baixos. Criticos: (1) FR-6 reagendamento sem mecanismo de re-entrada no pipeline do Poller; (2) FR-2 sem trajeto de dados para o texto/titulo da tarefa falado no lembrete. Altos: dimensao de Operacoes (falhas do Poller) silenciosa; AWS SAM sem trilha de pesquisa no memlog (corrigido nesta entrada). Aplicando fixes diretos exceto: contradicao sobre quem edita o PillarConfig (AD-5 diz Claude via CLI, mas FR-11 do PRD diz 'o proprio usuario') - fica para o usuario decidir.
- (change) Fixes aplicados pos-gate: AD-2 regra apertada (SessionEndedRequest->sem_resposta nomeado); AD-3 estendido com ConditionExpression para idempotencia, campos task_title/checkpoint_attempts, snapshot de pillar/purpose no momento da criacao; AD-4 payload simplificado para so task_id (Custom Task le o resto do DynamoDB - resolve trajeto de dados do FR-2); novo AD-7 para re-entrada de tarefas reagendadas no pipeline do Poller (FR-6); Capability Map corrigido (FR-12 nao usa AD-4, NFR-2 aponta pro Deferred); diagrama de conteineres ganhou o caminho de invocacao direta do FR-12; ERD atualizado; Deferred ganhou Operacoes do Poller, storage do token OAuth, e a lista das ~4 Rotinas que o usuario precisa criar manualmente na Alexa. Item aberto para o usuario: contradicao AD-5 vs FR-11 sobre quem edita o PillarConfig.
